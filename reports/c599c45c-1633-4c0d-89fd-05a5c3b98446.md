## Critical Findings

### REENTRANCY-001: Reentrancy Attack through Unsecured Use of Checkpoint Function in VotingEscrow

* **Severity:** High
* **Affected Function:** `VotingEscrow.checkpoint`
* **Description:** The `checkpoint` function in `VotingEscrow` is vulnerable to reentrancy attacks, allowing an attacker to drain funds or manipulate the contract's state.
* **Exploit Code:**
```solidity
pragma solidity ^0.8.0;
contract VotingEscrow {
    function checkpoint() public {
        // vulnerable code
    }
}
contract ReentrancyAttack {
    VotingEscrow public votingEscrow;
    function attack() public {
        votingEscrow.checkpoint();
        // reentrancy attack
    }
}
```
* **Defense Notes:** To prevent reentrancy attacks, the `checkpoint` function should be modified to use a reentrancy guard, such as OpenZeppelin's `ReentrancyGuard`. This will prevent an attacker from reentering the function and manipulating the contract's state.

### UNRESTRICTED-ACCESS-001: Unrestricted Access to Emissions Controllers in Trust

* **Severity:** High
* **Affected Function:** `Trust.setBaseEmissionsController`
* **Description:** The `setBaseEmissionsController` function in `Trust` does not have any access restrictions, allowing any user to modify the emissions controller.
* **Exploit Code:**
```solidity
pragma solidity ^0.8.0;
contract Trust {
    function setBaseEmissionsController(address _controller) public {
        // vulnerable code
    }
}
contract UnrestrictedAccessAttack {
    Trust public trust;
    function attack() public {
        trust.setBaseEmissionsController(address(this));
        // unrestricted access
    }
}
```
* **Defense Notes:** To fix this vulnerability, an `onlyOwner` modifier should be added to the `setBaseEmissionsController` function, restricting access to only the owner of the contract.

### UNPROTECTED-TRANSFER-001: Unprotected Use of TransferFrom in WrappedTrust

* **Severity:** High
* **Affected Function:** `WrappedTrust.transferFrom`
* **Description:** The `transferFrom` function in `WrappedTrust` does not check if the sender has sufficient balance before transferring funds, allowing an attacker to drain funds.
* **Exploit Code:**
```solidity
pragma solidity ^0.8.0;
contract WrappedTrust {
    function transferFrom(address _from, address _to, uint256 _amount) public {
        // vulnerable code
    }
}
contract UnprotectedTransferAttack {
    WrappedTrust public wrappedTrust;
    function attack() public {
        wrappedTrust.transferFrom(address(this), address(this), 100);
        // unprotected transfer
    }
}
```
* **Defense Notes:** To fix this vulnerability, a balance check should be added to the `transferFrom` function, ensuring that the sender has sufficient balance before transferring funds.
