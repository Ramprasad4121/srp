The NFT Dealers protocol underwent a comprehensive security audit focusing on reentrancy vulnerabilities, access control mechanisms, economic invariant violations, and oracle manipulation vectors. ### Tested Attack Vectors (Invalidated)

#### 1. Reentrancy via `buy()` → `safeTransfer`
**Hypothesis:** Malicious seller contract reenters during USDC transfer to extract multiple payments.  
**Validation:** `safeTransfer` used (reentrancy-safe). State updates (`delete listings[tokenId]`) occur before external calls. **Invalidated.**

#### 2. Supply Cap Bypass via Reentrancy
**Hypothesis:** Reentrant `mintNft()` calls bypass `totalMinted` checks.  
**Validation:** `totalMinted` incremented before external `transferFrom` call. Checks-Effects-Interactions pattern followed. **Invalidated.**

#### 3. Fee Tier Manipulation
**Hypothesis:** Price manipulation to force lower fee tier (1% vs 5%).  
**Validation:** Fee calculated deterministically from `listing.price` at purchase time; seller cannot modify price after listing without canceling/relisting. **Invalidated.**

## Recommendations

While no vulnerabilities were identified, the following best practices are recommended for ongoing security:

### 1. Formal Verification (Recommended)
Consider formal verification of the `calculateFees()` function to mathematically prove the progressive fee tier logic cannot produce values outside the {1%, 3%, 5%} set.

```solidity
// Specification to verify:
// forall price, fee(price) ∈ {1, 3, 5} 
// && fee(price) * price / 100 == actualFee
```

### 2. Access Control Monitoring (Recommended)
Implement off-chain monitoring for privileged functions (`revealCollection`, `whitelistWallet`, `removeWhitelistedWallet`) to detect anomalous owner activity:

```javascript
// Monitoring pseudo-code
if (msg.sender == owner && 
    functionSig in [whitelistWallet, removeWhitelistedWallet]) {
    alert("Privileged whitelist modification detected");
}
```

### 3. Circuit Breaker (Optional)
Consider implementing a pause mechanism for the secondary market (`buy()`, `list()`) in case of economic anomalies, separate from the irreversible `reveal` phase:

```solidity
bool public marketPaused;

modifier whenMarketActive() {
    require(!marketPaused, "Market paused");
    _;
}
```

### 4. USDC Token Validation (Recommended)
Add validation that the USDC contract address is not the zero address and implements standard ERC20 interfaces:

```solidity
constructor(address _usdc, ...) {
    require(_usdc != address(0), "Invalid USDC");
    require(IERC20(_usdc).totalSupply() >= 0, "Not ERC20"); // Static call check
    usdc = _usdc;
}
```
